# Profilers test plan

**Source:** [`tests/Profilers.spec.ts`](../tests/Profilers.spec.ts) · **Cases:** 27

Spatial and spectral profiles, formatting, smoothing, fitting and viewer connection.

## Setup and checks

- Run each Playwright case in a fresh page against the configured CARTA server. Use the existing fixture and helper calls named by the source test.
- Conversion and styling/smoothing cases explicitly use Cube Analysis and its docked spectral profiler. The connection case explicitly uses Default and a floating spectral profiler; neither setup depends on a previous test's saved layout.
- Check the requested widget/dialog state, data or store values, and the effect in the image viewer and applicable profiler. Treat a visible canvas alone as insufficient for a numerical result.
- For viewer or profile changes, compare a stable PNG with a reviewed baseline, including its rendered RGB values; inspect overlay text and numeric readouts as well.
- For rejected input or a failed operation, verify no unwanted image is created and the user can recover. Exercise every button relevant to the scenario.
- Referenced FITS fixtures: `HD163296_13CO_2-1_subimage.fits`, `IRCp10216_sci.spw0.cube.I.manual.pbcor.fits`, `IRCp10216_sci.spw0.cube.IQUV.manual.pbcor.subimage.fits`, `disk_0.fits`, `cube.fits`, `matching-cube.fits`, and `gaussian-emission-line.fits`. The matching cubes are lightweight 16×16 cubes with shifted spatial and spectral WCS; the Gaussian emission-line cube is a 16×16×31 mock with known line parameters generated by `test_data/create.mjs`.
- Current source contains named PNG baseline checks; the table below describes intended outcomes and does not claim any test has passed.

## Simultaneous spectral profiles

- **Overlays spectrally matched images and removes an unmatched image:** use `cube.fits` and `matching-cube.fits`, enable XY and Z matching in Image List, then enable Image mode and select both files. At cursor `(8,8)`, require two backend spectra `[1.5, 3, 6, 12, 24]` and `[3, 6, 12, 24, 48]`, with radio velocity axes `[0,1,2,3,4]` and `[2,3,4,5,6]` km/s and correct source labels. Disable Z matching and require only the reference spectrum to remain. Compare overlay and unmatched plot PNGs and save the viewer PNG.
- **Overlays multiple regions and removes a selected region:** create point regions `(8,4)` and `(8,12)` in `cube.fits`; enable Region mode and select both. Require separate labeled spectra `[1.25, 2.5, 5, 10, 20]` and `[1.75, 3.5, 7, 14, 28]`. Deselect Region 2 and attempt to deselect the final Region 1; its spectrum must remain. Compare overlay and remaining-region plot PNGs and save the viewer PNG.
- **Overlays multiple statistics and handles an unsupported cursor profile:** use a rectangle covering pixels x=6..10 and y=4..12 in `cube.fits`. Enable Statistic mode and select Mean and Max together. Require labeled spectra `[1.5, 3, 6, 12, 24]` and `[1.75, 3.5, 7, 14, 28]`. Remove Max and attempt to remove the final Mean; Mean must remain. Switching to Cursor disables the statistic menu and yields a single Sum spectrum; returning to Region 1 restores Mean and its rendered plot. Compare overlay and remaining-statistic PNGs and save the viewer PNG.
- All three cases inspect the actual rendered canvas RGB values: blue and orange curves must be present together, then orange must disappear when its series is removed. These tests cover UI selection, backend profiles and rendering together; frontend unit tests retain profile naming rules.

- Six independent cases cover PNG and TSV downloads for spatial X, spatial Y and spectral Z profiles using `cube.fits` at cursor `(8,8)`.

## Converted flux density regression (PR #2925)

Four cases reuse the generated five-channel cube pixels with new headers. Run `node test_data/create-flux-density.mjs` to regenerate `flux-k.fits`, `flux-pixel.fits`, `flux-beam.fits`, and `flux-no-pixels.fits`. Pixels are 3.6 × 7.2 arcsec and the Gaussian beam is 10.8 × 7.2 arcsec. The missing-pixel variant omits CRPIX1/2, which CARTA requires to calculate angular pixel sizes through WCS. Its spectral and beam metadata remain available.

- Select a rectangular region and record its native Sum spectrum. Check all five plotted FluxDensity channels against independently calculated pixel/beam integration factors and the Rayleigh–Jeans conversion at each channel frequency, with relative tolerance 1e-5 (2e-4 for the rounded Rayleigh–Jeans coefficient).
- Jy/pixel → Jy/arcsec² must preserve integrated Jy; MJy/sr gives the corresponding integrated MJy. Return to the native unit to catch stale conversion state.
- Jy/beam → Jy/arcsec² or MJy/sr uses pixel area divided by Gaussian beam area. Conversion to K must yield K·arcsec², without applying the intensity conversion twice.
- K → mK scales integrated values by 1000 and retains `mK*arcsec^2` in the plotted axis label. K → Jy/beam uses frequency-dependent conversion; returning to K restores the native integrated spectrum.
- Without pixel metadata, a converted Jy/beam → K flux profile must remain unavailable rather than use backend flux in the wrong unit. Wait for completed Sum data, require unavailable plotted values, then append a calibrated image and recover a finite Sum spectrum in the same profiler.
- Compare profile PNG baselines after each conversion and capture the viewer with settings closed. Export the recovered native spectrum and verify all five TSV values match the plotted values.

The frontend unit tests retain the conversion coefficient matrix. These E2E cases exercise real FITS metadata, backend statistics, region selection, unit menus, plotted series and exports together.
